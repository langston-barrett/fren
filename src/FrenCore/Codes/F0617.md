Testing never reached a check: it had no value in any test (a warning).

Erroneous code example:

```fren
proc c(q: Seq<Int>): (big?) {
  ensure r: big? iff q.len > 1000
  expect e: q[7] > 0 or big?
}
```

`fren quickcheck` found behaviours of the procedure, but in none of them
did `e` have a value: the search tries sequences of at most two elements,
so `q[7]` is always out of range, and the evaluator knows no value for an
index out of range. A test in which a check has no value says nothing
about it, so it does not count, and the check's result is inconclusive.
The same happens where a function has no value that the evaluator knows,
no case of a table or `match` is taken, or evaluation runs out of fuel,
and where the check's trigger, rather than the check, has no value: a
trigger without a value does not hold, but it is not false either. Where
the trigger had no value in every test in which it was not false, the
warning says so, at the trigger. An
assumption of the procedure that, as a whole, has no value in any input
admits none, so it has this warning beside `F0610`, which it explains. One
whose trigger has no value but which holds admits every input, and has
no warning there. Guard the part that has
no value, or rely on `fren check`:

```fren
proc c(q: Seq<Int>): (big?) {
  ensure r: big? iff q.len > 1000
  expect e: when q.len > 1, q[1] > 0 or big?
}
```
