A verdict of an expectation of a trait rests on the trait's laws, which Fren could not show can hold together with its assumptions.

Erroneous code example:

```fren
type Key

set_option fren.lint.undecidable "allow" in
trait Store {
    fn put(Self, Key, Int): Self
    fn get(Self, Key): Option<Int>

    law get_put(s: Self, k: Key, v: Int, j: Key): get(put(s, k, v), j) = (if j = k then Option::Some(v) else get(s, j))

    expect read_back(s: Self, k: Key, v: Int) { expect c: get(put(s, k, v), k) = Option::Some(v) }
}
```

A trait's expectation is checked with the trait's laws among its
hypotheses. Where the laws cannot hold together with its assumptions and
calls, every claim would hold, whatever it says. Where the expectation has
assumptions or calls, its vacuity under the laws checks that they can hold
together. Where it fails, that is `F0602`, and where it is not decided,
which, with quantified laws, it seldom is, a constraint whose verdict
comes from a proof under the laws says that it rests on them. An
expectation without assumptions or calls rests on the laws alone, whose
consistency Fren does not check yet. A counterexample meets the laws, so a
failure has no warning. An expectation of a trait without laws rests on
none, and has no warning:

```fren
trait Sized {
    fn size(Self): Int

    expect same(s: Self, t: Self) { expect c: when s = t, size(s) = size(t) }
}
```
