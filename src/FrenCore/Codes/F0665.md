A verdict of an expectation of a trait rests on the trait's laws, which no check showed can hold together.

Erroneous code example:

```fren
type Key

set_option fren.lint.undecidable "allow" in
trait Store {
    fn put(Self, Key, Int): Self
    fn get(Self, Key): Option<Int>

    law get_put(s: Self, k: Key, v: Int, j: Key): get(put(s, k, v), j) = (if j = k then Option::Some(v) else get(s, j))

    expect read_back(s: Self, k: Key, v: Int) { expect c: get(put(s, k, v), k) = Option::Some(v) }
}
```

A trait's expectation is checked with the trait's laws among its
hypotheses. Where the laws cannot hold together, every claim would hold,
whatever it says. Fren does not check yet that a trait's laws can hold
together, so a constraint of an expectation without assumptions or calls,
whose verdict comes from a proof under the laws, says that it rests on
them. An expectation with assumptions or calls has a check of its own,
whether they can hold together with the laws, whose failure is `F0602`,
and its constraints have no such warning. A counterexample meets the laws,
so a failure has no warning. An expectation of a trait without laws rests
on none, and has no warning:

```fren
trait Sized {
    fn size(Self): Int

    expect same(s: Self, t: Self) { expect c: when s = t, size(s) = size(t) }
}
```
